```sql
create index idx_products_category on public.products(category);
create index idx_products_status on public.products(status);

-- Row Level Security
alter table public.products enable row level security;

-- Políticas RLS: cada usuario solo ve/modifica sus propios productos
create policy "Users can view own products"
  on public.products for select
  using (auth.uid() = user_id);

create policy "Users can insert own products"
  on public.products for insert
  with check (auth.uid() = user_id);

create policy "Users can update own products"
  on public.products for update
  using (auth.uid() = user_id);

create policy "Users can delete own products"
  on public.products for delete
  using (auth.uid() = user_id);

-- Trigger para updated_at
create or replace function public.handle_updated_at()
returns trigger as $$
begin
  new.updated_at = now();
  return new;
end;
$$ language plpgsql;

create trigger set_updated_at
  before update on public.products
  for each row execute function public.handle_updated_at();
```

## 3. Autenticación

### 3.1 Android

**Stack tecnológico:**
- Supabase Auth SDK (Retrofit + OkHttp)
- Credential Manager + GoogleIdToken para Google OAuth
- SessionManager con EncryptedSharedPreferences (AndroidX Security Crypto)

**Flujo email/password:**
```
LoginScreen
  → ShoppingViewModel.signInWithEmail(email, password)
    → AuthRepository.signIn(email, password)
      → SupabaseAuthService.signInWithPassword(grant_type="password", body)
        → POST auth/v1/token?grant_type=password
    ← response: { access_token, refresh_token, user }
    → SessionManager.saveSession(accessToken, refreshToken, user)
    → setCurrentUser(user)
```

**Flujo Google OAuth:**
```
LoginScreen → boton Google
  → ShoppingViewModel.signInWithGoogle()
    → AuthRepository.signInWithGoogle(idToken)
      → SupabaseAuthService.signInWithIdToken(grant_type="id_token", body)
        → POST auth/v1/token?grant_type=id_token
```

**Sesión persistente:**
- `SessionManager` usa `EncryptedSharedPreferences` para almacenar tokens.
- Al iniciar la app, se restaura la sesión desde `SessionManager.restoreSession()`.
- `SessionManager.migrateLegacyPrefs()` migra datos de SharedPreferences planas a encriptadas.

### 3.2 Web

**Stack tecnológico:**
- `@supabase/supabase-js` v2.45.4
- Zustand `uiStore` para estado de sesión en memoria

**Flujo:**
```
AuthModal (login/signup)
  → signInWithEmail(email, password) / signUpWithEmail(email, password)
    → supabase.auth.signInWithPassword() / supabase.auth.signUp()
    ← success
    → useUIStore.setUser(user)

AuthModal (Google)
  → signInWithGoogle()
    → supabase.auth.signInWithOAuth({ provider: 'google' })
    ← redirect OAuth flow

Restauracion de sesion:
  Header.tsx useEffect
    → supabase.auth.getUser()
    → supabase.auth.onAuthStateChange() (listener activo)
```

```kotlin
// ProductDao.kt
@Dao
interface ProductDao {
    @Query("SELECT * FROM products WHERE userId = :userId OR userId = '' ORDER BY createdAt DESC")
    fun getProductsByUser(userId: String): Flow<List<ProductEntity>>

    @Query("SELECT * FROM products WHERE id = :id")
    suspend fun getProductById(id: Int): ProductEntity?

    @Query("SELECT DISTINCT category FROM products WHERE (userId = :userId OR userId = '') AND category != ''")
    fun getUniqueCategories(userId: String): Flow<List<String>>

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insert(product: ProductEntity): Long

    @Update
    suspend fun update(product: ProductEntity)

    @Delete
    suspend fun delete(product: ProductEntity)

    @Query("DELETE FROM products")
    suspend fun deleteAll()
}
```

### 4.6 Repositorios

```kotlin
// ProductRepository.kt
class ProductRepository(
    private val dao: ProductDao,
    private val supabase: SupabaseAuthService
) {
    // Operaciones locales (Room)
    fun getAllProducts(userId: String) = dao.getProductsByUser(userId)
    fun getCategories(userId: String) = dao.getUniqueCategories(userId)
    suspend fun save(product: ProductEntity) = dao.insert(product)
    suspend fun update(product: ProductEntity) = dao.update(product)
    suspend fun delete(product: ProductEntity) = dao.delete(product)

    // Sync con Supabase (futuro)
    suspend fun syncToSupabase(product: ProductEntity) {
        val session = SessionManager.getSession()
        if (session != null) {
            supabase.syncProduct(product, session.accessToken)
        }
    }
}

// AuthRepository.kt
class AuthRepository(
    private val authService: SupabaseAuthService,
    private val sessionManager: SessionManager
) {
    suspend fun signIn(email: String, password: String): AuthResponse
    suspend fun signUp(email: String, password: String, displayName: String): AuthResponse
    suspend fun signInWithGoogle(idToken: String): AuthResponse
    suspend fun signOut()
    fun restoreSession(): User?
}

```

```
  → Muestra badge con count (caps at 99+)
```

## 6. Grill Me — Diseño Propuesto

Asistente interactivo de decisión de compra. Evolución del `ComparadorScreen` de Android.

### 6.1 Flujo de Usuario

```
1. Usuario navega al Comparador / Grill Me
2. Selecciona una categoria
3. Selecciona 2+ productos de esa categoria
4. Presiona "Grill Me" (analizar con IA)
5. Se envia a Gemini un prompt especializado
6. Gemini responde con analisis comparativo estructurado
7. Se renderiza tabla comparativa + veredicto
```

### 6.2 Prompt de Gemini para Grill Me

```
Eres un asesor de compras imparcial. Compara estos productos y responde SOLO con JSON valido:

Productos:
[
  {"nombre": "Producto A", "precio": 299.99, "marca": "X", "pros": [...], "contras": [...], "score": 85, "calidad": 4},
  {"nombre": "Producto B", "precio": 399.99, "marca": "Y", "pros": [...], "contras": [...], "score": 78, "calidad": 5}
]

Responde este JSON:
{
  "tablaComparativa": [
    {"atributo": "Precio", "productoA": "$299.99", "productoB": "$399.99", "ganador": "A"},
    {"atributo": "Calidad", ...}
  ],
  "veredicto": "Texto explicando cual es mejor y por que...",
  "recomendacion": "Nombre del producto recomendado",
  "relacionCalidadPrecio": [
    {"producto": "A", "ratio": 8.5},
    {"producto": "B", "ratio": 7.2}
  ],
  "puntosClave": ["Resumen del analisis en 3-5 puntos"]
}
```

### 6.3 Implementación Android

Basado en el `ComparadorScreen` existente:

- **UI**: Agregar un modo "Grill Me" dentro de `ComparadorScreen` con checkbox de selección múltiple.
- **ViewModel**: Nuevo método `grillProducts(products: List<ProductEntity>)` que construye el prompt y llama a Gemini.
- **Resultado**: Nuevo `GrillResultScreen` que muestra tabla comparativa + veredicto.
- **Persistencia**: Opción de guardar el resultado en `notes` del producto o exportar a Markdown.

### 6.4 Implementación Web

- **Ruta**: `carrito-universal-web/src/pages/grill-me.astro`
- **Componentes**: `GrillSelector.tsx` (elegir productos), `GrillResult.tsx` (mostrar análisis).
- **Backend**: La web no tiene Gemini del lado cliente. Se necesita un API endpoint (Astro API route o Edge Function) que haga de proxy a Gemini con la API key del servidor.
- **Opcional**: Usar una Edge Function en Vercel o un API Route en Astro (`/api/grill`).

## 7. Estados de UI

Cada operación debe manejar 4 estados:

| Estado | Android (Compose) | Web (React) |
|---|---|---|
| **Loading** | `CircularProgressIndicator` + texto descriptivo | Spinner SVG animado + texto |
| **Empty** | Icono grande + título + subtítulo explicativo | SVG grande + texto + sugerencia |
| **Error** | `Toast` o `Snackbar` con mensaje | `div` con bg rojo claro + mensaje + borde |
| **Success** | Navegación o actualización de lista | Navegación o re-render |
